meters-nsk — постоянный доступ агента к серверу
================================================

Заполните:
  SSH_USER = ваш пользователь
  SERVER_IP = IP сервера

────────────────────────────────────
1. Ключ на Mac (один раз)
────────────────────────────────────

ssh-keygen -t ed25519 -f ~/.ssh/cursor_meters_nsk -C "cursor_meters_nsk" -N ""

────────────────────────────────────
2. Публичный ключ на сервер (один раз)
────────────────────────────────────

ssh-copy-id -i ~/.ssh/cursor_meters_nsk.pub SSH_USER@SERVER_IP

Проверка:
ssh SSH_USER@SERVER_IP "grep cursor_meters_nsk ~/.ssh/authorized_keys"

────────────────────────────────────
3. Секрет в Cursor (постоянно)
────────────────────────────────────

cat ~/.ssh/cursor_meters_nsk | pbcopy

Cursor → Settings → Secrets
  или  https://cursor.com/dashboard/cloud-agents → Secrets

Имя:     SSH_PRIVATE_KEY
Тип:     Runtime Secret
Значение: вставить из буфера → Сохранить

НЕ вставляйте ключ в чат.

────────────────────────────────────
4. Update Env (обязательно)
────────────────────────────────────

https://cursor.com/dashboard/cloud-agents
→ Start Setup Agent → Update Existing Env
(или Start Fresh, если окружения нет)

В репо уже есть:
  .cursor/environment.json
  .cursor/scripts/setup-ssh.sh

────────────────────────────────────
Почему раньше «вылетало»
────────────────────────────────────

• Ключ только на диске временной VM
• Новая сессия = новый пустой ~/.ssh
• Без Secrets ключ не подставляется

────────────────────────────────────
Ротация / удаление
────────────────────────────────────

Сервер:
ssh SSH_USER@SERVER_IP "sed -i '/cursor_meters_nsk/d' ~/.ssh/authorized_keys"

Mac:
rm -f ~/.ssh/cursor_meters_nsk ~/.ssh/cursor_meters_nsk.pub

Cursor:
удалить секрет SSH_PRIVATE_KEY → Update Env

────────────────────────────────────
Важно
────────────────────────────────────

• Только временный cursor_meters_nsk, не id_ed25519
• IP и пароли в git не коммитить
• Secrets + Update Env = доступ на постоянной основе
