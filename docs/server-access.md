## Доступ для Cloud Agent (Cursor)

Агент работает в облачном окружении и не имеет доступа к ключам на вашем Mac. Есть два способа дать ему доступ.

### Способ 1 — добавить публичный ключ агента на сервер

На Mac выполните одну команду:

```bash
echo 'ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIMQEyyZdY4Kj39MgNIEhCDHBaOminK1bDaNz7mHnSTFE cursor-cloud-agent' | ssh maxim@186.246.28.11 'mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys && echo OK'
```

В конце должно появиться `OK`. После этого напишите агенту **«готово»**.

**Плюсы:** не передаёте свой приватный ключ.  
**Минусы:** на сервере появится дополнительный ключ.

### Способ 2 — передать свой приватный ключ через Secrets (рекомендуется)

1. На Mac скопируйте приватный ключ:

```bash
cat ~/.ssh/id_ed25519
```

Если файла нет:

```bash
cat ~/.ssh/id_rsa
```

2. Скопируйте **весь** вывод, включая строки:

```
-----BEGIN OPENSSH PRIVATE KEY-----
...
-----END OPENSSH PRIVATE KEY-----
```

3. В Cursor: **Settings → Secrets**
4. Создайте секрет:
   - **Имя:** `SSH_PRIVATE_KEY`
   - **Значение:** весь приватный ключ целиком
5. Сохраните и напишите агенту **«готово»**

**Плюсы:** агент использует тот же ключ, что и вы.  
**Минусы:** приватный ключ попадает в секреты Cursor — после работы секрет можно удалить.

## Безопасность

- Не коммитьте приватные ключи и пароли в репозиторий.
- Root-пароль — только для веб-консоли Timeweb, не для SSH.
- После завершения работы с агентом:
  - удалите секрет `SSH_PRIVATE_KEY` из Cursor, **или**
  - уберите ключ `cursor-cloud-agent` из `~/.ssh/authorized_keys` на сервере.

### Удалить ключ агента с сервера

```bash
ssh maxim@186.246.28.11
sed -i '/cursor-cloud-agent/d' ~/.ssh/authorized_keys
```
